# g1_traj_finetune_v2 sim-to-real global goal 流程

目标：在 G1 机载电脑上，用 Mid-360 + Point-LIO 提供 `/odom`，用 RViz 发布全局目标点，外部脚本根据 `/odom` 闭环生成 base-frame 局部 `waypoints_b` 给 StepIt 策略。

流程：

```text
Mid-360
  |
livox_ros_driver2
  +--> /livox/lidar
  +--> /livox/imu
        |
catkin_point_lio_unilidar
        |
        +--> /odom

RViz /goal_pose
      +
/odom
      |
scripts/global_goal_to_waypoints.py
      |
      +--> /waypoints_b   std_msgs/msg/Float32MultiArray, 15 floats
      +--> /remain_time   std_msgs/msg/Float32MultiArray, 5 floats

zero heightmap publisher
      |
      +--> /height_scan_array std_msgs/msg/Float32MultiArray, 187 floats

StepIt g1_traj_finetune_v2_global
```

## 3. 发布平地 heightmap

平地测试先用全 0 heightmap。`/height_scan_array` 是 `std_msgs/msg/Float32MultiArray`，长度 187。

```bash
source /opt/ros/humble/setup.bash

python3 - <<'PY'
import rclpy
from rclpy.node import Node
from std_msgs.msg import Float32MultiArray

rclpy.init()
node = Node("zero_heightmap_pub")
pub = node.create_publisher(Float32MultiArray, "/height_scan_array", 10)
msg = Float32MultiArray()
msg.data = [0.0] * 187
node.create_timer(0.05, lambda: pub.publish(msg))
rclpy.spin(node)
PY
```

确认：

```bash
ros2 topic hz /height_scan_array
ros2 topic echo /height_scan_array --once
```

## 4. 启动全局目标转 waypoint 脚本

脚本接口和 sim-to-sim global 流程一致，只是 `/odom` 来源换成 Point-LIO。

```bash
cd /home/unitree/Workspace/Mirlab/stepit
source /opt/ros/humble/setup.bash

./scripts/global_goal_to_waypoints.py --ros-args \
  -p odom_topic:=/odom \
  -p goal_topic:=/goal_pose \
  -p waypoints_topic:=/waypoints_b \
  -p remain_time_topic:=/remain_time \
  -p debug_path_topic:=/global_goal_waypoints_path \
  -p v_des:=0.50 \
  -p min_speed:=0.08 \
  -p target_tolerance:=0.08 \
  -p heading_tolerance:=0.10 \
  -p slowdown_distance:=1.0 \
  -p final_heading_distance:=0.80 \
  -p yaw_rate_des:=0.80 \
  -p max_waypoint_distance:=1.35 \
  -p hold_goal:=true \
  -p use_goal_heading:=true
```

没有 RViz goal 时，脚本会持续发布零 `waypoints_b`，所以可以先启动 StepIt 并进入 PolicyOn，再点击目标。

确认输出：

```bash
ros2 topic hz /waypoints_b
ros2 topic echo /waypoints_b --once
ros2 topic echo /remain_time --once
ros2 topic echo /global_goal_waypoints_path --once
```

数据格式：

- `/waypoints_b`: 15 个 float，顺序为 `[x1,y1,h1, x2,y2,h2, ..., x5,y5,h5]`
- `x/y`: 当前 `base_link` 下的局部目标，单位 m
- `h`: 相对当前机身 yaw 的 heading，单位 rad
- `/remain_time`: 5 个 float，默认 `[0.5, 1.0, 1.5, 2.0, 2.5]`

到不了目标时优先调：

- 位置过冲：减小 `v_des` 或增大 `slowdown_distance`
- 最终方向转不过来：增大 `yaw_rate_des`，例如 `1.0`
- 太早开始转最终方向：减小 `final_heading_distance`
- 太晚才转最终方向：增大 `final_heading_distance`

## 7. 开调试模式启动 StepIt

在 G1 机载电脑上运行。不要用 sim-to-sim 的 `lo`。

当前机器上 `enP8p1s0` 是 `192.168.123.164/24`，通常用于和 Mid-360/机器人侧通信；如果现场 Unitree DDS 用别的网卡，需要改 `STEPIT_NETIF`。

```bash
cd /home/unitree/Workspace/Mirlab/stepit
source /opt/ros/humble/setup.bash

export STEPIT_NETIF=enP8p1s0
export STEPIT_UNITREE2_DOMAIN_ID=0
export STEPIT_PLUGIN_DIRS=$PWD/install/lib
export LD_LIBRARY_PATH=$PWD/install/lib:$PWD/extern/robot_sdk/unitree_sdk2/thirdparty/lib/$(uname -m):${LD_LIBRARY_PATH}

./install/bin/stepit \
  -P ros2 \
  -c console \
  -c joystick \
  -f joystick@unitree2 \
  -r g1 \
  -p neuro@$PWD/policies/g1_traj_finetune_v2_global \
  -- --ros-args --remap __ns:=/stepit
```

控制台顺序：

```text
Agent/StandUp
Agent/PolicyOn
```

`PolicyOn` 前先确认：

```bash
ros2 topic echo /waypoints_b --once
ros2 topic echo /remain_time --once
ros2 topic echo /height_scan_array --once
```

此时 `/waypoints_b` 应该是 15 个 0，或者至少还没有给出非零目标。

## 8. 启动 RViz

```bash
source /opt/ros/humble/setup.bash
rviz2
```

RViz 设置：

- Fixed Frame: `odom`
- 添加 `TF`
- 使用 `2D Goal Pose` 工具发目标
- 目标 topic: `/goal_pose`
- 添加 `Path` display，topic 选择 `/global_goal_waypoints_path`

`/global_goal_waypoints_path` 会显示脚本当前发给策略的 5 个全局前瞻点，用来判断 waypoint 是否在正确收敛到终点。

## 9. 启动顺序汇总

推荐按这个顺序开终端：

1. `/odom`: `ros2 launch point_lio mapping_mid360_stepit.launch.py`
2. `/height_scan_array`: 零 heightmap publisher
3. `/waypoints_b` 和 `/remain_time`: `global_goal_to_waypoints.py`
4. StepIt: `g1_traj_finetune_v2_global`
5. RViz: 发送 `/goal_pose`

每一步都先确认 topic：

```bash
ros2 topic hz /odom
ros2 topic hz /height_scan_array
ros2 topic hz /waypoints_b
ros2 topic echo /waypoints_b --once
```

实机第一次测试建议支撑/保护状态下进行。先保持零 waypoint 进入 `PolicyOn`，确认没有关节目标突变，再给很小目标，例如 0.05 m 或 0.10 m，逐步放大。

## 10. 真机前必须检查

- 继续用 `-r g1`，不要用 `g1_bfs`
- `STEPIT_NETIF` 必须是真机 Unitree SDK2 通信网卡，不要用 `lo`
- `STEPIT_UNITREE2_DOMAIN_ID` 必须和现场机器人 DDS domain 一致
- `/odom` 和 RViz `/goal_pose` 必须在同一个坐标系里，本流程统一用 `odom`
- 平地测试时 `/height_scan_array` 全 0
- Point-LIO `/odom` 漂移较大时，先不要放大目标距离
